自然生成中，也实际抓到了一次偏差

修复前：交付声明与实物不一致

任务要求“不得提及命令行”；GLM 自然生成的说明却写着“全程无需任何命令行或技术背景”，交付声明同时称未提及命令行。

修复后：同一文件，一次纠正

独立评审读文件后指出这条措辞约束，生产子任务删除了违规措辞。最终改为“全程在浏览器中操作，无需任何技术背景”。这证明一次实际约束检查与修复，不是复杂业务质量提升的证据。

案例：user-guide-natural / model-r2；初始内容来自原始 write_file 事件。其他自然组首答独立生成并已满足要求，因此本例不构成组间成功率提升。

这份证据说明什么

它验证小任务交付中的三件事：发现声明与实物之间的差距、保留合格结果、让拒绝反馈进入同一子任务继续修复。自然生成组用来观察强模型本来就能完成任务时的表现，不用预置错误组替代自然成功率。

这是一轮比赛前的工程小样本核查。每个自然任务每组只跑一次，首答独立生成；预置样例各组文件和声明一致，首次提交由脚本注入，后续所有评审与修复真实调用 GLM-5.3。没有将标准答案或独立测试传给运行时评审。人工式复核由 Codex 完成，并非第三方盲审。不能推出“任何模型或任务必然提升”，也没有测前端视觉质量、跨任务记忆学习收益或竞品性能。
